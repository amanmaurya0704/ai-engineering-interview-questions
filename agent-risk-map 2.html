01 — Ingestion
STAGE 1

Input & External Data Sources

User prompts, retrieved web pages, documents, emails, API responses feeding the agent's context.

Prompt Injection (Direct & Indirect) ▸

Malicious instructions embedded in user input or in external content (a webpage, PDF, email) that the agent reads and mistakes for legitimate commands, hijacking its behavior.

Mitigation
  • Treat all external/retrieved content as untrusted data, never as instructions
  • Separate instruction and data channels with structured delimiters or tagged roles
  • Run an injection-detection classifier on inputs before they reach the model
  • Restrict what actions can be triggered purely from document/tool content vs. verified user intent
  • Allowlist trusted data sources where feasible
Context / Instruction Confusion ▸

The agent fails to distinguish system prompt, developer instructions, tool output, and user input, letting lower-trust data override higher-trust instructions.

Mitigation
  • Enforce an explicit trust hierarchy: system > developer > verified user > tool/document output
  • Use structured prompt formats that tag the source of every piece of context
  • Re-assert core instructions after any untrusted content block
  • Test with adversarial "instruction override" content during evaluation
Agent Enumeration & Reconnaissance ▸

Attackers probe the agent's tool list, system prompt, or capabilities through crafted queries to map the attack surface before a targeted exploit.

Mitigation
  • Never reveal system prompts, tool schemas, or internal errors verbatim in responses
  • Rate-limit and monitor for repeated probing / boundary-testing patterns
  • Use generic error messages that don't leak internal architecture
02 — Reasoning
STAGE 2

Agent Core — LLM Planning & Decisions

The model interprets goals, plans steps, decides which tools to call, and scores confidence/risk.

Goal Hijacking ▸

An attacker subtly redirects the agent's objective to serve their own purposes while the plan still looks legitimate on the surface.

Mitigation
  • Define core goals immutably at the system level, not overridable by user or tool content
  • Run continuous goal-consistency checks comparing each step to the original objective
  • Flag and pause on plan drift or unexpected sub-goal creation
Decision and Approval Manipulation ▸

Attackers influence the model's confidence scores or approval thresholds so risky actions get auto-approved instead of escalated.

Mitigation
  • Compute risk/confidence scores in a component isolated from agent-controlled input
  • Sign or checksum approval thresholds so they can't be silently altered
  • Log every change to scoring logic or thresholds with attribution
Model / Tool Output Hallucination Exploitation ▸

Attackers craft inputs that induce plausible-looking but false outputs (fake citations, fake approvals) which downstream systems then trust.

Mitigation
  • Require evidence/citations for any high-stakes claim before acting on it
  • Cross-verify critical outputs against a trusted source before execution
  • Route low-confidence or unverifiable outputs to human review
03 — Memory
STAGE 3

Memory & Context Store

Short-term conversation state plus long-term / vector (RAG) stores persisted across turns or sessions.

Memory Poisoning ▸

Malicious data gets written into the agent's persistent memory, influencing its behavior in future sessions or for other users.

Mitigation
  • Validate and sanitize any content before it's committed to long-term memory
  • Namespace memory strictly per user/session — no cross-user bleed
  • Tag stored memories with provenance (source, time, trust level)
  • Require review before memory writes can influence high-impact future decisions
Vector / RAG Store Poisoning ▸

Malicious documents are planted in a retrieval index so they get pulled into context later and treated as trusted knowledge.

Mitigation
  • Vet and allowlist sources permitted to be indexed
  • Run periodic anomaly audits on retrieved chunks vs. known-good baselines
  • Keep provenance metadata attached to every retrieved chunk
  • Re-index and diff on a schedule to catch unexpected content changes
Sensitive Data Exposure ▸

PII, credentials, or confidential data inadvertently persists in agent context, memory, or logs where it can leak.

Mitigation
  • Classify data on ingestion; mask/redact sensitive fields before they enter context
  • Set short retention windows (TTL) on stored context
  • Strip secrets and PII from logs at write time, not after the fact
04 — Action
STAGE 4

Tool Calls & Execution

The agent invokes APIs, scripts, or system commands — the point where words become real-world effects.

Tool Abuse & Privilege Escalation ▸

Agents exploit overly permissive tools to perform unintended actions or reach resources they shouldn't have access to.

Mitigation
  • Grant each tool the minimum privilege it needs — nothing broader
  • Use scoped, short-lived credentials per task instead of standing access
  • Maintain explicit tool allowlists per agent role
  • Sandbox/isolate the tool execution environment from core systems
High-Impact Action Abuse ▸

Agents execute irreversible, financial, administrative, or externally visible operations without independent validation.

Mitigation
  • Require independent secondary validation for irreversible or financial actions
  • Use maker-checker (dual control) approval for critical operations
  • Support dry-run/simulation mode before real execution on high-stakes actions
Insecure Credential / Secret Handling ▸

Agents store or pass API keys, tokens, or session credentials in plaintext context, logs, or memory.

Mitigation
  • Store secrets in a dedicated secret manager, never inline in prompts or logs
  • Issue short-lived, scoped tokens with automatic rotation
  • Inject credentials at execution time only, out of the model's visible context
Denial of Wallet (DoW) ▸

Attacks that cause excessive API or compute costs by driving the agent into unbounded loops or repeated expensive calls.

Mitigation
  • Set hard budget/quota limits per session, user, and agent
  • Cap recursion depth and total tool-call count per task
  • Monitor spend in real time with automatic circuit breakers on spikes
Unbounded Agentic Loops / Resource Exhaustion ▸

Runaway recursive planning or repeated tool-calling loops that degrade availability, distinct from the cost-focused DoW risk above.

Mitigation
  • Enforce max iteration/step limits per task
  • Add timeouts and watchdog processes that kill stalled runs
  • Detect lack of progress (repeated identical states) and break the loop automatically
05 — Coordination
STAGE 5

Multi-Agent Communication

Sub-agents or peer agents exchange tasks, results, and trust signals with each other.

Cascading Failures ▸

A compromised agent in a multi-agent system propagates its bad state or malicious instructions to other agents downstream.

Mitigation
  • Place circuit breakers between agents to stop propagation of anomalous behavior
  • Validate inter-agent messages the same way you'd validate external input
  • Design for blast-radius containment (bulkheading) so one agent's failure stays local
Cross-Agent Trust Exploitation ▸

One agent assumes another agent's output is safe purely because it came from "another agent," skipping validation.

Mitigation
  • Apply zero-trust between agents — verify, don't assume, every inter-agent payload
  • Define explicit trust boundaries and verification protocols per agent pairing
Identity / Impersonation Spoofing ▸

An agent's credentials or identity are used to impersonate a user or another agent to gain unwarranted trust or access.

Mitigation
  • Use strong agent identity (mTLS, signed tokens) for every inter-agent call
  • Verify sender identity cryptographically before acting on a message
06 — Oversight
STAGE 6

Human-in-the-Loop / Approval Gate

Where a human is meant to review or authorize a high-impact action before it executes.

Excessive Autonomy ▸

Agents take high-impact actions without appropriate human oversight built into the workflow at all.

Mitigation
  • Tier autonomy by risk/reversibility — low-stakes actions auto-run, high-stakes ones gate
  • Require explicit human approval for anything irreversible or high-value
  • Build kill switches / circuit breakers reachable at any point in execution
Human-in-the-Loop Bypass (Rubber-Stamping) ▸

Approval steps exist but become pro-forma because humans habitually approve agent requests without real scrutiny.

Mitigation
  • Run randomized deep-dive audits of "approved" actions to check for rubber-stamping
  • Add friction that requires reviewers to engage with context, not just click approve
  • Track approval latency and patterns to flag suspiciously fast/uniform approvals
Overreliance / Automation Bias ▸

Humans trust agent decisions and outputs without verification, an organizational risk that compounds every other risk above.

Mitigation
  • Mandate genuine human review checkpoints for critical decisions, not just visibility
  • Train reviewers on agent failure modes so they know what to look for
  • Surface calibrated confidence, not just an answer, so reviewers can judge trust
07 — Output
STAGE 7

Response & Downstream Delivery

The final answer, file, or payload handed back to the user or piped into another system.

Data Exfiltration ▸

Sensitive information leaks out through tool calls, API requests, or the agent's final output.

Mitigation
  • Apply egress filtering / DLP scanning on outbound agent output and tool calls
  • Restrict network access from the execution environment to approved destinations
  • Monitor outbound calls for anomalous destinations or payload sizes
Insecure Output Handling ▸

Agent output is rendered in a UI or passed to another system without sanitization, enabling injection (e.g. XSS) in the consuming app.

Mitigation
  • Treat agent output as untrusted, just like user input, before rendering or piping it
  • Sanitize/encode output for the specific downstream context (HTML, SQL, shell, etc.)
  • Validate content type before it's consumed by another system
Cross-cutting — not tied to a single stage
Supply Chain Attacks ▸

Compromised third-party tools, plugins, models, or data sources that the agent depends on across every stage.

Mitigation
  • Vet and pin exact versions of tools, plugins, and models — no floating dependencies
  • Maintain an SBOM (software bill of materials) for all agent dependencies
  • Verify integrity via checksums/signatures before loading any external component
AI Console Malicious Configuration ▸

The AI developer console is compelled to consume data containing instructions that drive malicious changes to the agent's own configuration.

Mitigation
  • Require human review and version control for every config change
  • Separate the data plane from the control plane so content can't reach config
  • Sign configs and keep a one-click rollback path
Repudiation & Audit Gaps ▸

Missing or tamperable logging means malicious agent actions can't be traced back or attributed after the fact.

Mitigation
  • Use immutable, tamper-evident logging (write-once storage, hash chains)
  • Centralize audit logs with defined retention policy
  • Attribute every action to an identity and timestamp, human or agent
